# Changelog

<Callout title="Currently: login-free send/read via local-send / ax-read">
[`local-send`/`ax-read`](/docs/cli/local-send) give a fully login-free path for both sending and reading real messages. Server login (`login --save`/`login --manual`) is still broken on recent KakaoTalk macOS builds ([#20](https://github.com/JungHoonGhae/openkakao-cli/issues/20), [#22](https://github.com/JungHoonGhae/openkakao-cli/issues/22)) — **do not repeatedly retry it from an unregistered device, that can get your account's sub-device login blocked.**
</Callout>

This page highlights major releases. Every release, including v1.5 through v1.10, is in [`CHANGELOG.md`](https://github.com/JungHoonGhae/openkakao-cli/blob/main/CHANGELOG.md).

## v1.14.1

- Fixed: in a chat window wider than about 500 px, a file you sent was read as received, so `local-send-file` waited for its upload.

## v1.14.0

**Back up, search, react, and write like the user.**

- `ax-export` backs up a chat's whole history through KakaoTalk's own 텍스트 파일로 저장; `ax-search` finds old messages in it.
- `ax-read --expand` reads messages folded behind 전체보기.
- `ax-friends` / `ax-friend`: find friends, read and set the private memo, rename (device-owner authentication).
- `local-react` adds KakaoTalk reactions; `local-rename-chat` renames a chat for you.
- `style` learns the user's tone per chat so agents can match it.
- `ax-chats --unread` and `local-mark-read` clear years of ad-channel backlog without opening a chat.
- An invisible watermark marks tool-sent messages; `bench/run.sh` records release timings.
- Opening 채팅방 설정 is 1.4 s faster.

## v1.13.0

**Know which chat you are about to write to.**

- Every send, reply, edit and delete first prints the chat's member count, recent senders and last activity, and for a chat outside the allowlist its three newest messages.
- `chat_not_found` names chats that differ only in spacing (`우리 친구` → `우리친구`) with their last message.
- Long messages that KakaoTalk folds behind 전체보기 are verified instead of `delivery_uncertain`.
- `ax-read --json` gives `members`, `sender` and `outgoing`; times include the clock.
- Messages end with `⌞ₛₑₙₜ ᵥᵢₐ ₒₚₑₙₖₐₖₐₒ` instead of starting with `🤖 [Sent via openkakao]` (`[send] signature`, `--no-prefix`).
- New `--dangerously-skip-allowlist` skips device-owner authentication for chats outside the allowlist, after the person at the Mac sets `[safety] allow_skip_allowlist = true`.

## v1.12.0

**Photos and files are verified once uploaded, and messages can be deleted.**

- A photo or file is `sent` only once KakaoTalk finished the upload (the bubble shows 공유). A failed upload is `delivery_uncertain`, with KakaoTalk's own error text.
- A lone 확인/OK alert left over a chat window is dismissed before the next send; any other dialog is `chat_dialog_open`.
- **New `local-delete --for-everyone | --for-me`** uses KakaoTalk's own delete menu. A scope KakaoTalk does not offer (the memo chat, someone else's message, or more than 24 hours for everyone) is `delete_unavailable`, and nothing is deleted.
- File sends reach the preview in 1.8 s instead of 3.4 s.
- The agent skill now lives in this repository: `npx skills add JungHoonGhae/openkakao-cli`.

## v1.11.0

**No login, 0.4 s per verified send, just the official app.** It never does what reported account bans came from: no server login and no LOCO traffic.

| Task (Mac Studio, KakaoTalk 26.8) | v1.9 | v1.11 |
|---|---|---|
| Read an open chat (`ax-read`) | 26.8 s | **0.2 s** |
| Send, verified by its new bubble (`local-send`) | 44 s | **0.4 s** |
| Find and open a closed chat (`--open-if-needed`) | 6.5 s (v1.10) | **3.2 s** (worst case measured) |
| Touch ID for an allowlisted chat | every send | **none** |

- **`--open-if-needed` uses KakaoTalk's own chat search** instead of naming every chat-list row, and still matches exact chat names. A missing chat is reported in 1.6 s instead of about 6 s.
- **An allowlisted chat needs no per-send authentication.** A chat outside `[safety] allowed_send_chats` is flagged `⚠ NOT in [safety] allowed_send_chats` and needs device-owner authentication right before the commit.
- **New `ax-login [--account <id>]`** signs a signed-out KakaoTalk back in from the login keychain item `openkakao.kakaotalk`. The password never appears in argv or output, and `login_rejected` is never retried.
- **New `--pick <N>`** opens one of several chats that share a name, and always asks for device-owner authentication. **New `--discard-draft`** clears a composer draft after approval.
- **`--json` failures carry `disposition: {delivery, retry}`**, so an agent can tell whether a repeat could send twice.
- Fixed: KakaoTalk 26.8's read-only new-message preview bar was read as a composer draft and blocked sends with `composer_busy`.

## v1.4.0

**AX-only `local-send`, new `ax-read`, chat allowlist — un-deprecated.**

- **Project maintenance resumes.** Server login (`login --save`, `login --manual`) is still broken on recent KakaoTalk builds and remains unfixed (#15, #20, #22) — but `local-send` and the new `ax-read` now give a fully login-free path for both sending and reading, so the CLI is useful again without a working server session.
- **`local-send` rewritten to be entirely AX-based**, dropping its local-DB dependency. Signature changed from `local-send <chat_id> <message>` to `local-send <chat_name> <message>` — the local SQLCipher DB's key-derivation formula no longer matches current KakaoTalk builds, so chat-id lookups through it are no longer reliable. `local-send` now finds the chat by exact display-name match in KakaoTalk's Accessibility (AX) tree and verifies delivery by scraping the opened chat window's own message list.
- **New `ax-read <chat_name>`**: read the most recently visible messages in a chat via AX scraping — no server contact, no local DB access.
- **New `safety.allowed_send_chats`**: an exact-match allowlist `local-send` now requires for real sends, since AX-send has no chat-id to cross-check against.
- Fixed several AX bugs found while building this: wrong `AXTable` picked up when a chat window was already open, main window stuck on the Friends tab, and `AXSelectedRows` set on the wrong element.

## v1.1.0

**Safety-first defaults, local DB reading, dry-run, memo chat shortcut.**

- **LOCO write disabled by default**: `send`, `delete`, `edit`, `react` now require `safety.allow_loco_write = true` in config. Protects accounts from bans caused by unofficial protocol usage.
- **Local DB commands** (zero server contact):
  - `local-chats`: list chats from encrypted local KakaoTalk SQLite database
  - `local-read <chat_id>`: read messages from local DB
  - `local-search <query>`: full-text search across local DB
  - `local-schema`: dump database table schema
- **`--dry-run`** on all write commands: preview what would happen without making any LOCO call. Works even without `allow_loco_write`. Supports `--json`.
- **`send --me`**: send to memo chat (나와의 채팅) without specifying chat_id. Resolves the chat ID from local DB automatically.
- **`doctor` expanded**: now checks local DB access (IOPlatformUUID, userId, file existence, SQLCipher decryption) and LOCO write configuration status.
- **AGENTS.md**: new agent integration guide with safe/risky command classification and recommended workflows.
- `rusqlite` switched from `bundled` to `bundled-sqlcipher` for SQLCipher database support.

## v0.9.4

**Watch auto-reconnect backoff + Pilsner REST token + test coverage expansion.**

- `watch --reconnect-delay <sec>`: configurable initial reconnect backoff (default 2s, doubles each attempt).
- `watch --reconnect-max-delay <sec>`: cap on reconnect backoff (default 60s).
- `watch --max-reconnect` default changed from 5 → 10.
- `watch --json` now emits a `{"type":"reconnecting","attempt":N,"delay_secs":D,"reason":"..."}` NDJSON line on each reconnect attempt.
- `KakaoCredentials` carries an optional `rest_token` field for the ~138-char Cache.db bearer token required by `talk-pilsner.kakao.com` endpoints.
- `resolve_base_credentials()` auto-populates `rest_token` from Cache.db on startup — best-effort, non-blocking if Cache.db is locked.
- REST client selects the correct token per endpoint: `rest_token` for pilsner, `oauth_token` for katalk.
- `auth_flow`: Cache.db copy timeout no longer propagates as an error — gracefully falls back to `Ok(None)` so commands work even when KakaoTalk is locking the directory.
- Added 14 new unit tests: 11 for `export.rs` (ExportFormat parsing, resolve_author, JSON/CSV/TXT format) + 3 JSON output parsing tests (`doctor`, `auth-status`, `cache-stats`). 257 tests total, zero warnings.

## v0.9.3

**Local message cache integration.**

- `watch` now persists incoming messages (MSG and SYNCMSG packets) to a local SQLite cache.
- `read` merges local cache with LOCO-fetched messages, deduplicating by logId. Displays `[read] Merged N messages from local cache` when cache contributes new messages.
- `read` also back-fills the cache with LOCO results so future reads benefit from previously fetched history.
- New `get_messages(chat_id, limit)` API on `MessageDb` for ordered message retrieval.
- 3 new integration tests for `get_messages` (20 total message_db tests).

## v0.9.2

**Edit command + completion promise.**

- `edit <chat_id> <log_id> <message>`: edit messages via LOCO REWRITE command. Returns -203 on macOS (dtype=2 platform restriction) — implemented for future Android support.
- `--completion-promise`: global flag that prints `[DONE]` to stdout after any command completes successfully. Designed for LLM agent integration where the caller needs a reliable completion signal.
- E2E verified: MemoChat + Alice (send/completion-promise pass, edit blocked by macOS -203 as expected).
- 240 tests passing, zero clippy warnings.

## v0.9.1

**React command + SYNCACTION handler.**

- `react <chat_id> <log_id>`: add reaction to a message via LOCO ACTION command (type=1 = like).
- SYNCACTION push handler in `watch`: real-time reaction events from other users now appear in watch output.
- CI fix: version integration test now uses `env!("CARGO_PKG_VERSION")` instead of a hardcoded string.
- 240 tests passing, zero clippy warnings.

## v0.9.0

**Delete, mark-read, and protocol capture.**

- `delete <chat_id> <log_id>`: delete a message via LOCO DELETEMSG. Works in DM chats (creates feedType:14 deletion marker). Requires `-y` for non-interactive use.
- `mark-read <chat_id> <log_id>`: mark messages as read up to a logId via NOTIREAD (fire-and-forget).
- `watch --capture`: output unknown LOCO push packets as structured NDJSON for protocol reverse engineering.
- SYNCDLMSG handler: delete events from other users now trigger hooks/webhooks in watch mode.
- SYNCREWR handler: edit event placeholder (pending protocol confirmation).
- `probe --capture-pushes`: extended timeout (10s) idle listen mode for capturing push packets.
- Open-chat safety checks for delete (same `--force` override as send).

## v0.7.1

**LOGINLIST chatLog sync for faster reads.**

- `read` now passes the target chatId in the LOGINLIST `chatIds`/`maxIds` arrays during connection. The server returns recent messages (including received ones) in the login response's `chatLog` field, making the initial read faster and more complete.

- Messages from LOGINLIST `chatLog` are automatically deduplicated against SYNCMSG results by logId.
- Cache.db-free auto-relogin via `email_cmd` with 3-tier fallback for credential recovery.
